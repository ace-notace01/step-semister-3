# 🌿 Branch Architecture

This repository follows a **feature-branch workflow**.

```text
                              ┌─────────────────┐
                              │      main       │
                              │   README only   │
                              └────────┬────────┘
                                       │
       ┌──────────┬──────────┬─────────┼─────────┬──────────┐
       ▼          ▼          ▼         ▼         ▼          ▼
  feature/    feature/   feature/  feature/  feature/   feature/
   week1       week2      week3     week4     week5      week6
       │          │          │         │         │          │
       ▼          ▼          ▼         ▼         ▼          ▼
    Week 1     Week 2     Week 3    Week 4    Week 5     Week 6

  feature/week7  feature/week8  feature/week9  feature/week10  feature/week11
       │              │              │               │               │
       ▼              ▼              ▼               ▼               ▼
    Week 7         Week 8         Week 9          Week 10         Week 11
```

### 🔒 Branch Rule

Each weekly feature branch is created **directly from `main`**.

This keeps every week's work independent:

```text
feature/week1  → Week 1 only
feature/week2  → Week 2 only
feature/week3  → Week 3 only
...
feature/week10 → Week 10 only
feature/week11 → Week 11 only
```

> **No mixing weeks. No accidental carry-over. Clean history.**

# 🗂️ Project Organization

Every weekly feature branch follows the same root-level structure:

```text
step-semister-3/
│
├── README.md
│
├── PracticeProblems/
│   ├── ProblemTitle1.java
│   ├── ProblemTitle2.java
│   └── ...
│
└── AssignmentProblems/
    ├── ProblemTitle1.java
    ├── ProblemTitle2.java
    └── ...
```

The branch name identifies the week (`feature/week1`, `feature/week2`, etc.). The folders are kept directly at the repository root rather than inside another `WeekX` folder.

Assignments and practice problems are kept separately for easier navigation and evaluation.
